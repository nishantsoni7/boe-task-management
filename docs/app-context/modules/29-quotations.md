## 1. Purpose & users

- Replaces the separate Base44 quotation maker (boequotation.base44.app) for building and sending quotations, inside BOE One. It is the first phase of a larger plan: import of client files, an image studio, a pricing desk, confirm → PI draft, reports, and the Pricing module that learns from every quotation.
- Users: salespeople (mostly phones), managers and the pricing desk (see everyone's), the owner. Clients see only the link.
- BOE sells hospitality furniture in bulk: a quotation is built by **room type × rooms** ("Boho room × 56 rooms"), not as a flat list.

## 3. The model

- **Quotation** (`quotations`): number `QT-<initials>-<5 digits>` from 01001 (Base44 numbers reached QT-NS-00005, QT-AK-00019, QT-SS-00047, so they never repeat); client, company name and GSTIN (20270714000000), project, contact (name, phone, role), email (internal only), client type, delivery state, dimensions unit (`in` default or `cm`, one for the whole quotation), GST mode, discount %, fabric and packing amounts (₹), transport note, validity days (7), client notes, internal notes; owner; status.
- **Room types** (`quotation_areas`): name, style, multiplier (rooms), unit label.
- **Lines** (`quotation_lines`): name, size as the client writes it (free text; the quotation's unit is shown with it), **Remarks / customization** (column `spec`, up to 1,600 characters since 20270714000000), material, finish, quantity **per room** (× the room type's multiplier) **or fixed**, unit price (₹, before GST), GST rate (0/5/12/18/28; stored per line, chosen once for the quotation in the builder), picture, optional (shown, not counted), internal note. `client_note` (the old "Note for the client") is no longer typed: the migration copied each one into Remarks, the column and the printed "Note:" line stay for old versions.
- **History** (`quotation_events`): created, saved (lines, value), status (from, to, note), shared, unshared, opened by the client, converted (into a PI draft: from, pi_submission_id, draft_reference). Append-only by trigger.
- **PI link** (20270615000000): `quotations.pi_submission_id` (→ `order_submissions`, `on delete set null`, one quotation per draft) and `pi_linked_at`.
- **Totals are never stored.** `src/lib/quotations/math.ts` computes them for every screen; the list's "before GST" value is `quotation_value_before_gst` in SQL with the same rounding (line = round(qty × price); discount = round(subtotal × % / 100)). GST by rate group; fabric and packing are taxed at 18%; IGST or CGST + SGST (half each, rounded).
- **Statuses**: Draft → Sent → Negotiating → Confirmed / Lost / Archived. Creating the client link turns a Draft into Sent. Confirmed, Lost and Archived are locked; Reopen sets Negotiating; reopening a Confirmed one is Admin only. Lost needs a reason.

## 5. Database (`20270614000000_quotations_module.sql`)

- Registration: `app_modules` (sort 115), `permission_modules`, actions **view, create, edit, view_all** (default off), Admin role rows. Mirrored in `modules.ts`, `ENGINE_GATED_MODULE_KEYS` (18), `MODULE_ENFORCEMENT`, `MODULE_WORDS` (levels viewer and contributor; view_all is an authority).
- The four tables have RLS on, **no policy and no grant** for anon or authenticated: nothing reads or writes them directly. Everything is a SECURITY DEFINER function with `search_path = public, pg_temp`:
  - `quotation_actor()` internal: signed in, active, `module_entry_open('quotations')`, then view; returns create / edit / view_all / admin.
  - `quotation_my_access()`, `quotation_list(scope)` ('mine' or 'all'; all needs view_all or Admin; at most 500), `quotation_get(id)` (with owner name, `may_edit`, last 30 events), `quotation_create(data)`, `quotation_save(id, doc)` (whole document; replaces room types and lines; refuses `QUOTATION_STALE` when `expected_updated_at` differs), `quotation_set_status(id, status, note)`, `quotation_share(id, on)`.
  - `quotation_public(token)`: the only function open to **anon**. A 32-hex token; returns client-safe fields only (no internal notes, owner id, phone, token); null for an unknown, turned-off or archived link; records "opened" at most once per 30 minutes.
- Who may change a quotation: Admin; or its owner/creator with create or edit; or anybody with edit **and** view_all (the pricing desk). Who may see it: Admin, view_all, owner, creator.
- **Phase 2** (`20270615000000_quotation_pi_link.sql`): `quotation_get` also returns `pi` {id, draft_reference, status}; `quotation_link_pi(id, submission_id)` (authenticated only) accepts only a draft the CALLER made (`order_submissions.created_by`, status `draft`), a Sent or Negotiating quotation the caller may edit, not already linked, and a draft no other quotation holds; sets Confirmed and writes `converted`. Calling it again with the same draft returns the same. It writes nothing to Orders.
- **The conversion runs in the browser** (`src/lib/quotations/toPiDraft.ts`), as the upload page does: pictures fetched from the public bucket → `buildPiWorkbook` → `create_order_submission` → workbook to `order-files` (`workbookObjectPath`) → `POST /api/orders/import/process-draft` → `quotation_link_pi` → open `draftDetailHref`. A failure before the server saves discards the empty draft (`discardUnsavedDraft`, as the upload page); no answer from the server keeps it (it may still save).
- Pictures: public bucket `quotation-images` (JPEG, 3 MB), paths `{uploader}/{uuid}.jpg`; insert only through `quotation_can_upload(name)` (own folder, create or edit); delete only an own upload no line uses. The browser shrinks every picture to 1600 px JPEG first (`toJpeg` from Inventory).

## 6. Business rules (defaults taken on the owner's behalf, 2026-11-12)

1. A module of its own, "Quotations", next to Sales; Admin only until granted per person.
2. Numbers keep the Base44 shape, QT-initials-5 digits, from 01001.
3. GST: BOE is registered in Rajasthan, so a Rajasthan delivery starts on CGST + SGST and any other state on IGST; the builder warns when the chosen mode does not match the state. (The real Resort Shamshabad quote printed CGST + SGST for a site outside Rajasthan.)
4. The printed terms are the PI sheet's, word for word (7 expectations, 23 terms, the closing line), including payment 70% / 30%. The contradictions found in the sheet (a 50% note, the system's 40% PI gate) are not resolved here: a later terms library takes one payment setting.
5. Validity counts from the day the quotation is sent (or made, before that); default 7 days, as the terms say.
6. A client link always shows the latest **saved** version. Sending is WhatsApp with the text filled in (wa.me); the person presses send. Opening the link is recorded and the page says so.
7. Archive, never delete.
14. (Owner, 2026-11-12) Price hints are shown to everyone who makes quotations (prices only, never client names). Price approval starts at: discount above 5%, or a product below 90% of its last ordered price; an administrator changes the limits on the Quotations page (empty = off). A client link that is already on stays on when prices change later (known limit: only turning a link on, and Confirm → PI, wait for approval).
13. (Owner, 2026-11-12) Image studio: one paid image request per press (about US$0.15), never retried; product pictures (not people or documents) go to the image provider; the result is a new picture, the old one stays in storage until nothing uses it.
12. (Owner, 2026-11-12; **amended 2026-11-14**) A client's BOQ brings no prices; **a BOE PI does** (owner, 14 Nov: "take prices and all other details of products mentioned in the uploaded PI"). The price is read from a column headed the way BOE's PI template heads it ("Cost per piece", "Original price", "Unit price", "Price per piece", or a bare "Cost"); a column headed only "Price", "Rate", "Net rate", "BOE - Price", "Pricing" or "Amount per pc" is read too but **shaded** for a person to check (a client's BOQ can head its own rate that way), and a template heading in the same sheet always wins; a second price column ("additional", "sample", "suggested", "alternative", "fabric", "packing", "option") and a US-dollar column are never the price. A PDF or photo still never brings a price. BOQ PDFs and photos MAY be sent whole to the Anthropic API to be read (an owner exception to "client names and phones never go to AI"); the file is not stored, and the reader is told not to copy names, phones, emails, addresses or prices. Excel, CSV and pasted rows never leave the browser.
8. (Owner approved, 2026-11-12) Confirm → PI draft goes through the Upload PI path, never a new write into Orders. The PI gets the quotation flattened: one row per non-optional product, named "Room type · Product", quantity = per room × rooms (or the fixed quantity), material in Material, finish + specification + client note in Customization, the discount as an amount, fabric, packing and transport in the footer, one GST figure ("GST @ 18%" when every line and the extras share one rate; otherwise each rate on its own lines, labelled "GST").
9. Every product needs a name, a quantity, a price above ₹0 and a **picture** before Confirm: the PI reader refuses a product without a picture (`PRODUCT_IMAGE_REQUIRED` is blocking in process-draft), and a placeholder would put a wrong photograph on a client document.
10. The person who presses Confirm owns the PI draft (Orders shows a draft only to its maker), and needs Order Management → Create.
11. **Leads are not touched** (owner, 2026-11-12): Lead Board rule 8 of 2026-11-03 ("Converted is a record only, no link to Orders") stands.

## 7. Traps

- Pricing (20270617000000): `quotation_price_history` computes word lists for every approved PI line on each call (no index); fine for thousands of lines, slow for hundreds of thousands. `quotation_get`, `quotation_share` and `quotation_link_pi` were re-created there: the latest definitions are in 20270617000000.

- The working tree is CRLF under `core.autocrlf`; scripted edits must normalise line endings or anchors miss.
- `quotation_public` is volatile (it writes the "opened" event); do not make it stable to "optimise" it.
- `quotation_save` deletes and re-inserts room types and lines, so their ids change on every save: nothing may hold a line id across saves (a later PI conversion must read lines at the moment it converts).
- Fabric and packing go into the 18% GST group even when no furniture line is 18%.
- Import of a PI (2026-11-14): the price column is a heading list in `HEADERS` (key `price`, and `priceWeak` for the plain headings, which shade the cell) with `NOT_THE_PRICE` as the guard of both, a PI's "Customization(s)" is key `custom` (joined into Remarks after "Details"; the word is `customi`, never bare `custom`, which would take "Customer"), and the Price column in the review table belongs to the FILE (`hasPrices`, set when the rows are taken), so clearing every price does not remove the column. The PI's Code column, "BOE Remarks" (internal), fabric and packing columns, the footer (discount, fabric, packing, GST) and the header (client, phone, project) are NOT imported. Prices are rounded to whole rupees (the column is `bigint`). A row with several pictures keeps the leftmost (`picturesBySheet` sorts by row, then column); a picture anchored one row off its product is not taken. The PI's "Terms and Conditions" block is not imported: the quotation prints the standard terms (`terms.ts`) on every quotation and the PI template carries the same text. Real PIs also come as PDFs and in older layouts (a separate "Height" column, "Remark" and "Comments" both): the first matching column of each kind wins.
- Import: a heading word is matched by the START of the normalised heading; never add a bare "no" (it would take "Notes"). A row with a name but no quantity, size or serial number is a room title. The route body limit is Vercel's 4.5 MB, so PDFs over 4 MB are refused in the browser; maxDuration 60 s.
- Import reads Excel through `xlsx` / `exceljs`, which the page downloads the first time a file is chosen. After a deploy an open tab can fail that download (`Failed to load chunk … from module …`) and keeps the failure until it reloads. `readFailure()` (`importFile.ts`) turns it into a plain sentence and the dialog offers a Reload page button (2026-11-13, PR #756 `c9670dd0`, no SQL). Do not make it reload by itself: the builder saves by hand, and it warns before leaving only while there are unsaved edits. Other lazy loaders (the PI workbook download, Excel exports) still show the raw text.
- `Pic` (`src/components/quotations/Pic.tsx`) is the one place `<img>` is allowed for this module's pictures.
- The PI workbook must keep the PI template's labels (`TEMPLATE_HEADERS` from the parser, the header labels, the footer labels in G with amounts in I, I115 = discount). `piWorkbook.test.ts` reads it back with the real parser: change the generator or the parser, run it.
- PI money is paise (`numeric(12,2)`), quotation money whole rupees: a fractional quantity can make the PI differ from the quotation by under a rupee.
- `toLines` used `Number(tax_rate) || 18`, which read a 0% line back as 18%; fixed in phase 2 (`quotations.test.tsx` pins it).

## 12. Price learning, piece 1 (owner approved 2026-11-13; LIVE 2026-11-14: PR #760 `b273b165`; migration `20270715000000_pricing_learning.sql` APPLIED before the merge, after a backup)

**What it is.** A place in Quotations to feed the price model with the PIs BOE has already made, 25 at a time, with an honest score for every batch, and a doorway on every suggested price to share feedback or to say how the price logic should work. Planned with the owner on 2026-11-13: plan, then a seven-screen mock-up (private design page https://claude.ai/artifact/BNkKqkj38XYNTUMKgRH2qd), approved, then built. Pieces 2 (order-level patterns: designs, total pieces, order value; step-by-step reasoning) and 3 (the desk changes the logic: pins, name rules, left-out, weights, a change log, a test on past PIs) are not built.

**Who.** The pricing desk: Admin, or Quotations edit AND see-all (the same rule as price approval, `pricing_learning_require_desk()` in the database, `isDesk()` in `components/pricing/learning/common.ts`). Salespeople never see the page; they see the suggested price and the feedback doorway.

**Pages** (`src/components/pricing/learning/`, all inside `QuotationsLayout`, nav item "Price learning" for the desk only):
- `/quotations/learning` (`LearningHome`): the average miss of the latest batch against the first, PIs and lines learned, the miss and the within-±10% charts per batch (`charts.tsx`; the target of 8% is the constant `TARGET_MISS`), the batch list, and the feedback list (`FeedbackInbox`). First visit shows an invitation.
- `/quotations/learning/new` (`LearningNew` with `StepFiles`, `StepCheck`, `StepTest`): choose up to 25 .xlsx/.xls files → check what was read → blind test → learn. The whole batch lives in the page (no draft); the browser warns before the page is left.
- `/quotations/learning/[id]` (`LearningBatch`): one learned batch with its PIs (file names show here).

**The reader** (`src/lib/pricing/learning/readPi.ts`, pure; `piFile.ts` adds SheetJS, the file hash, and `File.lastModified` as a date fallback; pictures are never read). The strict PI reader (`src/lib/pi`) opened **0 of 60** sampled old PIs, so this one finds the table by column NAMES: Name/Description/Item, Quantity/Qty, Dimension/LxDxH/Size, Material/Details, Customization/Remarks, Cost per piece/Original price/Price/Rate, Total cost/Total. A second price column ("additional PU cost", "material suggested by us", "sample price", "fabric") is never the price. Lines run to the Sub Total row (a footer row has a label and no product name). It works out the third of quantity / price / total from the other two and flags it. It reads Sub Total, Discount and Grand Total from the footer and compares Σ quantity × price with the Sub Total (tolerance max(₹2, 0.2%)). Currency from the heading ((USD) / (INR)). PI date from a "Date" / "PI date" label near the top (Excel number or written date, 2015 to today + 2 days). A line whose name says "sample" is flagged and starts unticked. `judge()` says ready / check / left out: left out = no table, no priced lines (a quantities-only list), US dollars; check = an odd price, a total that differs, a Sub Total that does not match, a missing date. A size we cannot place, and a worked-out figure, are shown but do not block.
- **Proof on the owner's real files (14 Nov 2026, 60 of 307 PI .xlsx under `C:\BOE New\Inquiry`, sampled evenly, counts only):** table found 60/60; 54 with priced lines; 31 ready, 21 to check (14 had no date, 7 a Sub Total that differs), 8 left out (5 quantities-only lists, 2 in US dollars, 1 layout without a readable price); Sub Total matched 43 of the 50 files that had one; PI date found in 43; median 10 lines per PI, average 18, largest 103; about 4 seconds for 60 files. The worked-out-figure rule never fired on this sample (the 5 files with no lines are quantities-only lists, not blank cells).

**Order of a batch** (`batch.ts`, pure): `initialReview` marks each file learn / left out (already seen by file hash or by its lines, the same PI twice in the batch, a verdict of left out, or an older version of one project: two PIs sharing at least 4 and 70% of their product names keep only the later); `learned()` needs at least one ticked line; `blockers()` (nothing to learn, a bad date, more than 25 files); `testLinesOf()`; `buildSaveDoc()` (a PI with lines but left out is saved with its reason, so it is not asked about again; a file with no lines at all, and a copy inside the batch, are not saved).

**The blind test** (`blindTest.ts`, pure). For each ticked line of the PIs being learned: the model's price from `fitType` + `predict(fit, features, yearsAgo)` using the price pool BEFORE this batch (one `fetchPool` per product type, because one call takes at most 40 words), priced **as of the PI's own date** (`predict` gained `yearsAgo`, default 0, so a quotation line is unchanged). Score: average |miss| in percent over the lines it could price, share within ±10%, the whole-order gap (Σ quantity × price), by product type, the six biggest misses. Lines of a type with fewer than 8 prices, or no type, are "could not price". The browser works the score out and the save keeps it with the batch (a desk tool: the score is not security sensitive).

**Database** (`20270715000000_pricing_learning.sql`; four tables, all with RLS on, no policy, no grant): `pricing_learning_batches` (batch_no, score), `pricing_learning_pis` (source_label = the file name, DESK ONLY; `file_hash` and `content_print` both unique; pi_date and where it came from; pieces, designs, subtotal, discount, value_before_gst; left_out + reason), `pricing_learning_lines` (name, size, material, customization, qty, unit_price, derived, left_out), `pricing_feedback`. Functions: `pricing_learning_access()`, `pricing_learning_home()`, `pricing_learning_known(hashes, prints)`, `pricing_learning_save(doc)` (one step; a duplicate or a bad value refuses the whole batch; a refused save does not use up a batch number), `pricing_learning_batch(id)`, `pricing_feedback_add(doc)` (anyone who may open Quotations; at most 60 a day each), `pricing_feedback_list(open_only)` and `pricing_feedback_set(id, status, note)` (desk only). `pricing_all_points` (20270620000000) and `pricing_pool` (20270621000000) are re-created with the learned lines as kind `order`, dated by the PI, last three years; the pool cap goes from 800 to 2,500. Neither returns a file name.

**Feedback and correction doorway** (owner, 2026-11-13: "always give an option to share feedback or correct the price logic"). `SuggestionFeedback` sits under every suggested price on a quotation line (through `PriceHintLine`'s `feedback` prop, passed by `LineRow` and `BuilderScreen`; it shows for a model or history suggestion, also on a quotation that can no longer be edited) and beside each big miss of a blind test. Two modes: share feedback (too high, too low, wrong kind of product, a detail misread, something else, an optional price the person would quote, a comment) or correct the logic (a few words on how it should work; saved as kind `correction`). It stores the line, the client type, what the model said (price, range, confidence, reasons, basis) and the quotation. The desk reads it in the feedback list and marks it seen, done or declined with a note. **Changing the logic from that list is piece 3**; until then a correction is a note for the desk, not a switch.

**Owner decisions (2026-11-13):** learned PIs count like approved PIs (weight 1.0); US-dollar files are left out, not converted; the learned price is the per-piece price printed on the PI before its lump-sum discount (as approved PIs count today); the file name is kept for the desk only; no saved drafts. The client type uses the quotation's five types, default "Not specified" (a type given to the learned PIs while approved PIs have none would teach the model a client-type effect that is not real).

**Traps.**
- Apply the migration BEFORE the merge: the pages call the new functions, and `pricing_pool` is re-created.
- `file_hash` and `content_print` are unique over every PI ever saved, left out ones included: re-uploading a left-out file says "already seen". Deleting a batch deletes its PIs and lines (cascade).
- `pricing_pool` still takes at most 40 words and returns at most 2,500 points: the blind test asks once per product type.
- `fitType` needs at least 8 prices of a type and varied features; a pool whose points all share one size makes the matrix singular and the type "could not price".
- `predict(fit, f, yearsAgo)`: only the blind test passes `yearsAgo`.
- The reader stops collecting products at the first Sub Total row; a product named "Packing stool" is a product (a footer row has no product name or fewer than three numbers).
- The regex `s` flag does not compile under the ES2017 target (`tsc` fails): use `[\s\S]`.
- `learning.module.css` classes used by the TSX must exist; `learning.dom.test.tsx` checks it.
